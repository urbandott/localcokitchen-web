# LocalCoKitchen Next.js Migration Report

Date: 2026-06-23

## Migration summary

The app now has a production-buildable Next.js App Router implementation alongside the existing static files. Public marketing and menu pages are server-rendered. Auth, account, cook, and admin sections are route-grouped and marked noindex. Supabase access is centralized through typed server/browser clients using the publishable key only.

## Architecture

- `app/` contains App Router pages, layouts, sitemap, robots, health route, and proxy.
- `components/` contains shared shell components.
- `features/` contains feature-owned auth, admin, cart, kitchen, and menu logic.
- `lib/` contains auth/session, Supabase clients, validation, security, SEO, and formatting helpers.
- `types/` contains typed Supabase row/RPC contracts.
- `tests/` contains Vitest and Playwright tests.

## Security decisions

- No service-role key is used by the Next.js app.
- Browser and server Supabase clients use publishable key + RLS.
- Admin authorization uses the existing `lck_identity.current_user_is_admin` RPC.
- Private route groups are `noindex` and forced dynamic.
- Proxy refreshes Supabase sessions and adds `X-Robots-Tag` to private route responses.
- Secure headers and CSP are configured in `next.config.ts`.
- Auth server actions use generic messages to avoid account enumeration.
- Redirect targets are constrained to local paths.
- Customer menu data comes from a narrow public RPC and excludes private cook fields.
- Cart totals are client-side UX only; checkout must revalidate price, quantity, availability, cook status, and totals server-side.

## SEO and performance improvements

- Public pages are server-rendered.
- Route metadata includes canonical, Open Graph, Twitter, and robots directives.
- `robots.ts` and `sitemap.ts` are generated by Next.js.
- Images are served from `public/images` and Next image optimization is enabled for Supabase image URLs.
- Client JavaScript is isolated primarily to menu/cart/auth forms.
- Private and auth routes are noindexed.

## Remaining risks

- Full cook dashboard write workflows are not yet rebuilt as rich Next.js forms; the migrated `/my-kitchen/` page currently provides a protected dashboard/read view.
- Admin application review details/actions are not yet rebuilt to full legacy UI depth; admin cook list and kitchen moderation action are migrated.
- Production deployment requires real `NEXT_PUBLIC_SUPABASE_URL`, `NEXT_PUBLIC_SUPABASE_PUBLISHABLE_KEY`, and migration reconciliation.
- Checkout/order/payment flows are still not implemented in this codebase.
- Lighthouse was not run in this terminal session; Playwright smoke and Next build were run instead.
